# Store settings, languages and display currencies

Store settings is organized into General, Regional, Business, SEO, Orders & documents and Currencies tabs with one shared save action. Inputs remain mounted when switching tabs, and validation opens the first tab containing an error. It includes business profile, SEO defaults, base currency, units, timezone, storefront display currencies and a shortcut to the dedicated Languages page. Additional display currencies use manually maintained rates defined as units of that currency per one base-currency unit. Changing the base currency clears old rates unless new rates are supplied. The currency selector remembers the shopper choice for catalog and cart browsing. Converted prices are estimates; checkout, payment gateways, invoices, order history and financial records use the original base currency. Conversion uses decimal arithmetic and currency minor-unit precision. Source amounts remain unchanged. Recently viewed cards from a different display currency are hidden until revisited.

The ISO 639-1 language catalog is managed only in Languages. Store settings links to that page. Enable the languages your store needs and provide catalog and interface translations through the existing translation tools. Selecting a language does not automatically translate content. Missing translations fall back to the default. Arabic, Hebrew, Persian, Urdu and other RTL languages set storefront direction to RTL. The theme remains responsible for script-compatible fonts and specialized layout details.

## Order and document preferences

Orders & documents is a Store settings tab. The old documents settings URL redirects to that tab. The shared save action includes notification preferences, invoice numbering, seller document details and order numbering in one transaction. Existing order and invoice identifiers stay unchanged. Order prefixes accept letters, numbers, hyphens, underscores and `{year}`; digit count controls zero padding. Starting/next counters may only move forward. Counters are initialized above existing identifiers, allocated under a database lock inside checkout transactions, and rolled back when checkout fails. Unchanged fields from an older settings screen never move a live counter backward.
