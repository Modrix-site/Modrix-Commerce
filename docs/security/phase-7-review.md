# Security Review and Remediation Report — Phase 7 (1.0.0-rc.1)

- **Date:** 2026-10-13
- **Scope:** the whole repository at the release candidate: core, bundled modules and themes, marketplace server and client, deployment templates and CI.
- **Method:** the review follows master specification §17 and the OWASP Top 10 and ASVS level 2 areas, using:
    - code review of every request entry point (routes, middleware, controllers, webhooks, the license API, the installer);
    - dependency audits;
    - automated tests for each control;
    - a browser check of the shipped headers;
    - an axe-core accessibility audit.
- **Limits:** this is an internal review, not an independent penetration test. Recommendation R1 below covers that.

## Findings

| ID  | Severity               | Finding                                                                                                                                                                                                                                        | Resolution                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | Critical (dev tooling) | `tinypool` ≤ 2.1.1 (GHSA-5gmw-xhrv-c9v3, GHSA-85c8-ppgw-ccpr: prototype-pollution gadget leading to code execution) through `vite-plus` → `oxfmt`. Build-time only, not shipped, and exploitable only with attacker-controlled worker options. | **Fixed:** pinned `tinypool@2.1.2` with an npm override. `npm audit` reports 0 vulnerabilities. CI now also fails on critical advisories in build tooling.                                                                                                                                                                                                                                                                        |
| F2  | High                   | Application pages sent no browser security headers: no CSP, no frame protection outside the sample Nginx config, no HSTS. Any HTML injection would have run script freely, and admin pages could be framed for clickjacking.                   | **Fixed:** `SecurityHeaders` middleware (ADR-036) sends a nonce-based `script-src` (no `unsafe-inline` or `unsafe-eval` for scripts), `frame-ancestors 'none'` with `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, COOP, and HSTS on HTTPS. Tested in `SecurityHeadersTest`, and checked in the browser on the storefront, cart, checkout, admin, settings and Appearance pages with no violations. |
| F3  | High                   | The last active owner could delete their own account from Settings → Profile, leaving a store with no owner. The escalation guards prevented this everywhere else.                                                                             | **Fixed:** account deletion applies the same last-owner guard. Tested.                                                                                                                                                                                                                                                                                                                                                            |
| F4  | High                   | The sample Nginx config set `X-Frame-Options: SAMEORIGIN` while the app now sends `DENY`. Conflicting duplicate headers can make browsers ignore both.                                                                                         | **Fixed:** Nginx no longer sets application security headers. It adds `nosniff` and a sandbox CSP for `/storage/` media, plus caching for `/build/`.                                                                                                                                                                                                                                                                              |
| F5  | Medium                 | Password-reset requests and registration were not rate limited per IP. The reset broker throttles per email address only, so mail flooding across many addresses was possible.                                                                 | **Fixed:** `auth-sensitive` limiter (5 per minute per IP) on forgot-password, reset-password and register. Tested.                                                                                                                                                                                                                                                                                                                |
| F6  | Medium                 | Web installer setup tokens never expired. A token copied into deploy logs stayed valid until installation.                                                                                                                                     | **Fixed:** tokens expire after 24 h (configurable) and are replaced on the next visit. `ECOMODULAR_WEB_INSTALLER=false` disables the web installer for CLI installs. Tested.                                                                                                                                                                                                                                                      |
| F7  | Medium                 | There was no tested backup or restore, and backups were not encrypted (a spec §17 and Phase 7 requirement).                                                                                                                                    | **Fixed:** `ecomodular:backup` and `ecomodular:restore` (ADR-037) with AES-256 encryption, a SHA-256 manifest, path-safe extraction, credentials kept out of process lists, and rollback of files on a failed import. The drill is demonstrated in tests (see `docs/operations/backup-and-restore.md`).                                                                                                                           |
| F8  | Medium (accepted)      | `style-src` allows `'unsafe-inline'`, because theme tokens and component styles are rendered inline. CSS injection could restyle a page, but it cannot run script.                                                                             | **Accepted, with mitigation:** theme values are validated against a strict vocabulary before they reach CSS (ADR-031), and React escapes all text. Revisit if style nonces become practical with the UI libraries.                                                                                                                                                                                                                |
| F9  | Low                    | Deleting an account that holds marketplace licenses or orders failed with a 500 error (foreign key `restrict`).                                                                                                                                | **Fixed:** a clear validation message is shown instead. Records are kept for the buyer and for accounting. Tested.                                                                                                                                                                                                                                                                                                                |
| F10 | Low                    | Silently discarded mass-assignment attribute in `SaveAttribute` (harmless; the value was set explicitly).                                                                                                                                      | **Fixed:** removed. `preventSilentlyDiscardingAttributes` and `preventLazyLoading` are now on outside production, so such issues fail the tests.                                                                                                                                                                                                                                                                                  |
| F11 | Low                    | Each cart view wrote every cart line (an N+1 write), which amplifies load under bot traffic.                                                                                                                                                   | **Fixed:** only changed lines are written. Query-budget tests guard the list pages.                                                                                                                                                                                                                                                                                                                                               |
| F12 | Low (accepted)         | When a marketplace release is withdrawn for security reasons, stores that already installed it are not notified in their admin.                                                                                                                | **Accepted, with mitigation; closed in Phase 8.3:** signed security advisories now reach stores through the license API and appear in the Marketplace page and the health check.                                                                                                                                                                                                                                                  |

## Controls verified (spec §17)

| Area                                                         | Status and evidence                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authentication, email verification, password reset, sessions | Fortify with 2FA and passkeys; login 5 per minute; reset and registration per IP (F5); verified-email middleware; session regenerated on login; secure, HTTP-only, SameSite=Lax cookies (`SESSION_SECURE_COOKIE` is checked by health in production)                                      |
| Authorization and privilege escalation                       | Server-side `can:` on every admin route (`AdminAccessTest`); escalation guard (`RoleEscalationTest`); last-owner guard, now also on account deletion (F3); password confirmation for 13 sensitive route groups                                                                            |
| CSRF                                                         | Laravel CSRF on every session route. The stateless license API and webhooks are outside the session, and are authenticated by license keys and signatures                                                                                                                                 |
| XSS and output escaping                                      | React escaping, with no user HTML rendered (the only `dangerouslySetInnerHTML` is the server-generated 2FA QR SVG); nonce CSP (F2)                                                                                                                                                        |
| SQL injection                                                | Eloquent and the query builder with bindings; `LIKE` input escaped (`App\Support\Like`)                                                                                                                                                                                                   |
| SSRF                                                         | No user-supplied URLs are fetched. The marketplace client calls only the configured URL and refuses download URLs from any other origin                                                                                                                                                   |
| Path traversal and archive handling                          | Module, theme and marketplace archives scanned (no `..`, absolute paths or symlinks; size and count limits; manual extraction); theme assets served by an allow-listing route; backup restore checks every path (F7)                                                                      |
| Unsafe uploads and image processing                          | Images re-encoded (appended payloads stripped, tested); theme packages data-only; only `index.php` executes (Nginx); `/storage/` sandboxed (F4)                                                                                                                                           |
| Package signatures and integrity                             | Ed25519 signatures plus SHA-256 and size checks, verified before files change (ADR-034; tamper tests)                                                                                                                                                                                     |
| Rate limits                                                  | Login, 2FA, passkeys, password reset, registration, checkout, license API (60 per minute), webhooks (600 per minute), installer (5 per minute), uploads, health (60 per minute)                                                                                                           |
| Secret management                                            | `.env` only; gateway credentials encrypted and write-only; license keys hashed and encrypted; installer and backup passwords never on the command line; exceptions never flash passwords or tokens; health and status pages never show credentials or paths                               |
| Payment and webhook verification                             | Stripe signatures verified with tolerance; deduplication inbox; redirects never mark orders paid; amounts reconciled (Phase 3 tests)                                                                                                                                                      |
| Admin audit logs                                             | Append-only, with secret-like keys redacted; now also records backups created and restored                                                                                                                                                                                                |
| HTTPS deployment                                             | HSTS on HTTPS; the health check fails `APP_DEBUG` in production and warns on non-HTTPS `APP_URL`; trusted-proxy guidance in the deployment guide                                                                                                                                          |
| Mass assignment                                              | Explicit `fillable` or `forceFill` with validated data; discarded attributes now fail outside production (F10)                                                                                                                                                                            |
| Data minimisation and privacy                                | Card data never stored; logs exclude credentials; customers can delete their accounts (orders and the customer record are kept for accounting, unlinked from the deleted login); no third-party trackers or external scripts. A self-service personal-data export is not implemented (R3) |
| Dependency checks                                            | `composer audit`: 0 advisories. `npm audit`: 0 (F1). Both run in CI                                                                                                                                                                                                                       |
| Backups                                                      | Encrypted, checksummed, access-restricted (mode 600 in a private directory), drill-tested (F7)                                                                                                                                                                                            |
| Incident and takedown process                                | `SECURITY.md`                                                                                                                                                                                                                                                                             |
| Untrusted input                                              | Marketplace packages, extension metadata, theme assets, CSV imports (with formula neutralisation on export), webhook payloads and license API input are all validated as untrusted                                                                                                        |

## Residual risks and recommendations

- **R1:** commission an independent penetration test before taking card-present or high-volume traffic.
- **R2:** modules run trusted code inside the application process (ADR-029). Only enable reviewed modules. Third-party modules need isolation first (Phase 8).
- **R3:** add a self-service personal-data export to match GDPR access requests (Phase 8). Until then, operators answer requests from the admin's customer and order views.
- **R4:** the MySQL backup and restore path is exercised in CI only. Run one restore into staging on MySQL before going live.
- **R5:** if TLS terminates at a proxy, configure trusted proxies so HTTPS detection, HSTS and secure cookies behave correctly.
